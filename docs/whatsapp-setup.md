# Подключение WhatsApp Business к FloralAI

## Как это работает для владельца бизнеса

Владелец регистрируется в FloralAI, сохраняет профиль и услуги/каталог, активирует пробный период или подписку и открывает «Каналы → WhatsApp». Он подтверждает доступ к своему номеру в окне Meta. Сервер обменивает код авторизации на токен, проверяет приложение, разрешения и принадлежность номера выбранному WhatsApp Business Account, затем подписывает аккаунт на webhook. В обычном Cloud API режиме сервер также регистрирует номер с указанным владельцем PIN.

Каждому владельцу соответствует один собственный номер. Один номер нельзя перезаписать на другой аккаунт FloralAI. Переписка и контекст ограничены владельцем и номером клиента. Добавление бота обычным контактом в личный WhatsApp не выполняет такого подключения.

## Первый шаг: создать приложение Meta

Компания (Business Portfolio) и приложение — разные объекты. Откройте [Мои приложения](https://developers.facebook.com/apps/) под тем же аккаунтом Meta. Если FloralAI уже есть в списке, откройте его. Иначе создайте приложение FloralAI для работы с WhatsApp и свяжите с компанией.

Название приложения и App ID можно передавать для настройки. App Secret, access tokens, PIN и ключи Supabase должны попадать только в серверные переменные среды, не в чат, Git или клиентский JavaScript.

## Настройка приложения платформы

1. Настройте WhatsApp Business Platform и Facebook Login for Business / Embedded Signup. Сохраните App ID, App Secret, Configuration ID и выбранную в Meta версию Graph API.
2. Добавьте `floral-ai-pi.vercel.app` в разрешённые домены приложения и JavaScript SDK. Настройте OAuth по требованиям текущей конфигурации Facebook Login for Business. Не используйте `/api/whatsapp/connect` как redirect callback: приложение получает код через JavaScript SDK и отправляет его туда POST-запросом.
3. Для подключения сторонних компаний пройдите onboarding Tech Provider, проверки бизнеса, приложения и доступа, требуемые Meta. Конфигурация должна запрашивать `whatsapp_business_management` и `whatsapp_business_messaging`; дополнительные разрешения, включая `business_management`, включайте по требованиям выбранного onboarding. До одобрения тестируйте только разрешённые Meta тестовые активы и пользователей с ролью в приложении.
4. Укажите действительную политику конфиденциальности и процедуру удаления данных, а также остальные сведения, запрошенные Meta. Не используйте заглушки юридических документов или контактов.
5. Задайте webhook URL: `https://floral-ai-pi.vercel.app/api/whatsapp/webhook`. Verify token должен совпадать с `WHATSAPP_WEBHOOK_VERIFY_TOKEN`. Подпишитесь на поле `messages` объекта WhatsApp Business Account. GET проверяет verify token; POST проверяет `X-Hub-Signature-256` по App Secret и исходным байтам тела.

Официальные материалы: [Meta Embedded Signup](https://developers.facebook.com/documentation/business-messaging/whatsapp/embedded-signup/overview), [программа Tech Provider](https://whatsappbusiness.com/partners/become-a-partner/), [Meta Cloud API в Postman](https://www.postman.com/meta/whatsapp-business-platform/collection/wlk6lh4/whatsapp-cloud-api).

## Переменные Vercel

Используйте `.env.example` как список. Добавьте в Production и нужные тестовые окружения:

| Переменная | Значение |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` и public publishable/anon key | Уже используемый проект FloralAI |
| `SUPABASE_SERVICE_ROLE_KEY` | Серверный ключ этого же проекта; никогда не добавляйте `NEXT_PUBLIC_` |
| `META_APP_ID` | App ID приложения FloralAI |
| `META_APP_SECRET` | App Secret |
| `META_WHATSAPP_CONFIG_ID` | ID конфигурации Embedded Signup |
| `META_GRAPH_VERSION` | Поддерживаемая версия из Meta App Dashboard, в формате `vNN.0`; значение намеренно не угадано в коде |
| `WHATSAPP_WEBHOOK_VERIFY_TOKEN` | Отдельная случайная строка для проверки webhook |
| `WHATSAPP_TOKEN_ENCRYPTION_KEY` | 32 случайных байта в hex, то есть 64 символа |
| `WHATSAPP_ENABLED` | `true` после настройки Meta и базы |
| `WHATSAPP_COEXISTENCE_ENABLED` | `true` только после получения соответствующего доступа Meta |
| `WHATSAPP_RETRY_SECRET` | Отдельный случайный секрет для восстановительной очереди |

Ключ шифрования можно сгенерировать локально: `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. Сохраните значение в менеджере секретов. Не меняйте его при обычном деплое: зашифрованные токены иначе нельзя будет расшифровать. Смена ключа требует отдельной процедуры повторного подключения/перешифрования.

Для свободных ответов модели используются существующие серверные `OPENAI_API_KEY`, `OPENAI_MODEL` и `USE_MOCK_AI=false`. Без них WhatsApp отвечает на частые вопросы по сохранённым адресу, графику, услугам, товарам и доставке, а интерфейс явно показывает этот режим. Сценарные ответы «демо-запись создана» в WhatsApp не используются. Ключ модели не требуется владельцам отдельных магазинов.

После изменения переменных выполните redeploy. Таблицы создаёт миграция `20261024105921_whatsapp_business_channel.sql`; они независимы от Telegram и Prisma-демонстрации. Миграция применена к текущему проекту FloralAI. Для другого окружения примените её перед включением канала.

## Отдельный номер и текущий WhatsApp Business

- Режим Cloud API предназначен для отдельного номера. Он использует PIN двухэтапной проверки. Пользователь задаёт и сохраняет PIN; приложение не хранит PIN после регистрации.
- Для сохранения текущего приложения WhatsApp Business требуется доступный для номера режим Coexistence. При включённом `WHATSAPP_COEXISTENCE_ENABLED` интерфейс предлагает его отдельно и запускает `whatsapp_business_app_onboarding`. Повторная регистрация `/register` в этом режиме не вызывается. Доступность определяет Meta. Не переводите работающий личный или бизнес-номер через обычный Cloud API flow без выбора подходящего пути.
- Если Meta вернула только WABA ID, автоматически выбирается номер только при единственном доступном номере. При нескольких номерах требуется повторить flow с выбором номера; код не угадывает номер.

## Ответы, пауза и восстановление

Автоответы отправляются только на входящие сообщения и в пределах 24 часов от соответствующего сообщения. Исходящих рассылок и шаблонов здесь нет. Голосовые, фото и документы пока получают просьбу написать текстом; содержимое медиа не анализируется.

Владелец видит последние 30 диалогов и последние 30 входящих сообщений с сохранёнными ответами в «Каналы → WhatsApp». Обновление запускается кнопкой; это пока не общий список диалогов Telegram и WhatsApp. Бот не создаёт WhatsApp-заказы или записи автоматически и не сообщает об их создании. Для этого нужен сотрудник.

Слова «оператор», «сотрудник», «agent» и аналогичные запросы останавливают бота в диалоге; вопрос остаётся в кабинете. Уведомление владельцу через SMS/email не отправляется. Владелец может сам приостановить диалог и вернуть его боту. При ответе непосредственно из WhatsApp Business сначала приостановите бота в кабинете: синхронизация исходящих сообщений сотрудника и истории Coexistence пока не реализована.

Входящие сообщения сохраняются до обработки. Уникальный message ID предотвращает второе событие; lease одного диалога блокирует одновременную обработку разными запросами. Готовый ответ сохраняется до отправки; после успешного подтверждения от WhatsApp повторный webhook его не отправляет. Ошибки дают `503` для повторной доставки Meta. При неоднозначной сетевой ошибке после принятия сообщения Meta, но до получения/сохранения подтверждения, строго однократная отправка не гарантируется — API не предоставляет используемому запросу общего ключа идемпотентности.

Для восстановления после аварийного завершения запроса настройте доверенный планировщик на `POST /api/whatsapp/retry` с `Authorization: Bearer <WHATSAPP_RETRY_SECRET>`. Планировщик и частота здесь не создаются автоматически. Endpoint ограничивает объём работы и не принимает от вызывающего номера, тексты или owner ID. Просроченные ответы не отправляются.

Проверки: `npm test`, `npm run build`, интеграционный SQL `supabase/tests/whatsapp_channel.sql` с `ROLLBACK`. После настройки Meta дополнительно обязательно проверить настоящий Embedded Signup, реальное входящее сообщение, ответ, паузу, запрос сотрудника и отзыв доступа. До этого нельзя утверждать, что живое подключение WhatsApp проверено.
